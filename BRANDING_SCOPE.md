# QGroundStation: межі ребрендингу

## Статус документа

- Етап: 0 — фіксація меж ребрендингу.
- Статус: погоджено.
- Дата фіксації: 20 листопада 2026 року.
- Цільові платформи: Windows та Android.
- Поза поточним обсягом: Linux, macOS та iOS.

## Мета

Очистити застосунок від видимого кастомного бренду 49KS/GroundStation і повернути офіційний візуальний стиль QGroundControl. Оскільки ця версія функціонально відрізняється від офіційної, її видима назва та необхідні технічні ідентифікатори мають бути окремими, щоб QGroundStation можна було встановити одночасно з офіційним QGroundControl.

Ребрендинг не повинен змінювати функціональні доробки, компонування інтерфейсу або спеціальні елементи керування.

## Канонічна назва

Єдина видима назва застосунку:

```text
QGroundStation
```

Правила використання:

- назва всюди пишеться як `QGroundStation`;
- назва не перекладається;
- не використовуються варіанти `GroundStation`, `Q Ground Station`, `49KS QGroundStation` або інші похідні;
- у видимому UI не повинно бути окремої назви `GroundStation`; входження цього тексту як частини `QGroundStation` є правильним.

Цільові build-значення:

```makefile
TARGET         = QGroundStation
QGC_APP_NAME   = QGroundStation
```

Цільове compile-time значення:

```text
QGC_APPLICATION_NAME = QGroundStation
```

## Видимі та внутрішні згадки

Користувацькі тексти, що називають поточний застосунок, змінюються на `QGroundStation`.

Назва `QGroundControl` залишається без змін у таких випадках:

- QML imports та resource namespaces;
- назви C++ класів, API, типів і внутрішніх об'єктів;
- назви вихідних каталогів;
- ліцензійні заголовки та copyright;
- юридичні й історичні згадки;
- посилання на upstream-проєкт та його документацію;
- назви сторонніх протоколів і компонентів.

Глобальна автоматична заміна `QGroundControl` заборонена. Кожне видиме входження перевіряється за контекстом.

## Візуальний обсяг

До ребрендингу входять:

- видима назва застосунку;
- офіційні логотипи QGroundControl;
- application icons;
- splash screen;
- логотипи в toolbar, налаштуваннях, на карті та в інших видимих місцях;
- платформні іконки Windows та Android.

Не входять до ребрендингу:

- кольорова палітра функціонального UI;
- шрифти;
- компонування екранів;
- спеціальні кнопки;
- керування камерою, відео та телеметрією;
- інші функціональні доробки.

## Джерело офіційних ресурсів

Використовуються лише готові ресурси з актуального офіційного upstream QGroundControl.

Правила:

- перед інтеграцією оновити `upstream` і зафіксувати точний commit hash;
- використовувати офіційні SVG як першоджерело;
- PNG та ICO копіювати або генерувати тільки з того самого офіційного комплекту;
- перевірити сумісність SVG з версією Qt цієї гілки;
- не створювати власний варіант ресурсу, якщо його немає в upstream;
- якщо кастомний ресурс не має офіційного аналога, прибрати його використання і відтворити поведінку upstream;
- зберігати офіційні внутрішні імена ресурсів QGC.

На момент фіксації документа локальний `upstream/master` вказує на:

```text
2af411ce0de35c42ce0b06182e95a31bd7bd8745
```

Цей hash є довідковим. Остаточний hash джерела ресурсів фіксується безпосередньо перед їх інтеграцією.

## Organization та профіль налаштувань

Погоджені значення:

```makefile
QGC_ORG_NAME   = QGroundStation.org
QGC_ORG_DOMAIN = org.qgroundstation
```

QGroundStation отримує повністю новий профіль налаштувань. Міграція з таких профілів не виконується:

- `49KS`;
- `GroundStation`;
- офіційний `QGroundControl`.

Каталоги даних і логів, які залежать від application name або organization, мають бути окремими для QGroundStation.

## Кеш карт

### Windows

Зберігається поточна реалізація спільного кешу карт через `QStandardPaths::GenericCacheLocation` і каталог `QGCMapCache300`. Якщо версії формату кешу сумісні, QGroundStation та офіційний QGroundControl можуть використовувати цей кеш спільно.

### Android

Кеш карт залишається у приватному sandbox застосунку. Через окремий package ID він не буде спільним з офіційним QGroundControl. Реалізація спільного Android-кешу не входить у поточний обсяг.

## Android

Цільовий package ID:

```text
org.mavlink.qgroundstation
```

Це забезпечує:

- паралельне встановлення з офіційним QGroundControl;
- незалежний Android sandbox;
- незалежні налаштування та приватні дані;
- відсутність взаємодії з офіційними оновленнями QGroundControl.

Власний механізм оновлення QGroundStation не входить у поточний обсяг.

Поточний keystore залишається без змін. Його назва та невидимі технічні згадки 49KS не є частиною візуального ребрендингу.

### Android splash screen

Якщо актуальний upstream містить офіційний splash screen, він адаптується до Qt/Android механізму цієї гілки.

Правила:

- використовувати лише офіційні ресурси;
- не створювати додаткові portrait/landscape логотипи, якщо їх немає в upstream;
- прибрати дубльовані або застарілі splash metadata;
- залишити мінімальну конфігурацію, потрібну для Qt 5;
- перевірити запуск у portrait та landscape орієнтаціях.

## Windows installer

QGroundStation повинен мати незалежну install/uninstall identity.

Цільові назви:

```text
QGroundStation.exe
QGroundStation-installer.exe
QGroundStation-Uninstall.exe
```

Цільовий каталог встановлення:

```text
C:\Program Files\QGroundStation
```

Installer повинен:

- встановлюватися поруч із QGroundControl;
- не видаляти й не змінювати офіційний QGroundControl;
- коректно перевстановлювати QGroundStation;
- під час майбутнього оновлення знаходити та замінювати попередню версію QGroundStation;
- створювати окремі ярлики та uninstall registry entry.

Каталог crash dumps:

```text
%LOCALAPPDATA%\QGroundStationCrashDumps
```

Системний ключ драйверів залишається спільним:

```text
SOFTWARE\QGroundControlUAVDrivers
```

Він описує глобально встановлені драйвери, а не профіль застосунку.

## Очищення 49KS/GroundStation

Потрібно:

- прибрати старий бренд із видимого UI;
- припинити використання `KSLogo*` в активних QRC та UI-посиланнях;
- замінити видимі `49KS` і окреме `GroundStation` на погоджений бренд;
- перевіряти невидимі технічні згадки індивідуально.

Не потрібно:

- видаляти всі фізичні файли старих ресурсів;
- перейменовувати функціональні компоненти лише через `KS49` у назві;
- змінювати keystore;
- видаляти код, який реалізує потрібну функціональність;
- очищати історію Git.

## Юридичні згадки

У поточному обсязі не змінюються:

- copyright;
- ліцензійні заголовки;
- авторство;
- юридичні посилання;
- About/legal information;
- згадки про upstream QGroundControl.

Юридичне оформлення QGroundStation може бути виконане окремим завданням за запитом замовника.

## Критерії готовності ребрендингу

Робота вважається завершеною, коли:

- у видимому UI немає бренду `49KS`;
- у видимому UI немає окремої назви `GroundStation`;
- видима назва всюди має точне написання `QGroundStation`;
- користувацькі згадки поточного застосунку використовують `QGroundStation`;
- технічні, юридичні та історичні згадки `QGroundControl` збережені;
- використовуються офіційні логотипи та іконки QGroundControl;
- немає зламаних ресурсних посилань;
- Windows executable та installer мають погоджені назви й офіційні іконки;
- Windows install/uninstall identity не конфліктує з QGroundControl;
- Android має package ID `org.mavlink.qgroundstation`;
- Android має назву `QGroundStation`, офіційну іконку та адаптований офіційний splash screen;
- QGroundStation використовує новий незалежний профіль налаштувань;
- міграція з 49KS/GroundStation свідомо не виконується;
- кеш карт Windows може залишатися спільним;
- Android-кеш залишається окремим;
- функціональні доробки не змінені;
- Windows build проходить;
- Android build проходить;
- усі залишкові технічні згадки `QGroundControl` або 49KS не є видимим кастомним брендингом.

## Подальші етапи

1. Перейменувати застосунок на `QGroundStation` без заміни візуальних ресурсів.
2. Зафіксувати й інтегрувати актуальний комплект офіційних ресурсів QGroundControl.
3. Відновити офіційні логотипи в UI.
4. Оновити Windows packaging та installer identity.
5. Оновити Android branding, package identity та splash screen.
6. Прибрати активні посилання на старий бренд.
7. Виконати пошук залишків, збірку та візуальну перевірку.
